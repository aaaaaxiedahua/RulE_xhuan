方案1：Query-Conditioned Rule Attention（查询感知的规则注意力）            
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：现在的模型对所有规则一视同仁。比如你要预测 (张三, 配偶, ?) 时，所有规则头是"配偶"的规则都会被同等对待。
                                                                             
  改进思路：不同的查询应该对不同的规则有不同的关注度。                       
                                                                             
  具体例子                                                                   
                                                                             
  假设你在Kinship数据集中要预测：                                            
  - 查询1：(Alice, aunt, ?)  // Alice的姨妈是谁？                            
  - 查询2：(Bob, aunt, ?)    // Bob的姨妈是谁？                              
                                                                             
  数据库里有两条规则：                                                       
  - 规则A：mother ∧ sister → aunt（妈妈的姐妹是姨妈）                        
  - 规则B：father ∧ sister → aunt（爸爸的姐妹也是姨妈）                      
                                                                             
  当前方法的问题：                                                           
  两条规则对所有查询的权重都一样。但实际上：                                 
  - 如果Alice的数据里有很多"mother"关系的记录，规则A应该更重要               
  - 如果Bob的数据里只有"father"关系，那规则B应该更重要                       
                                                                             
  Query-Conditioned的做法：                                                  
  模型会看查询中的头实体（Alice或Bob）的embedding，结合关系（aunt）的embedding，动态决定：
  - 对Alice的查询：规则A权重=0.8，规则B权重=0.3                              
  - 对Bob的查询：规则A权重=0.2，规则B权重=0.9                                
                                                                             
  为什么有效？                                                               
                                                                             
  类比到实际生活：                                                           
  你要找"谁是我的亲戚"这个问题，你会根据：                                   
  - 我自己的家庭背景（头实体特征）                                           
  - 我要找的是什么关系（关系类型）                                           
  来决定哪些推理路径更靠谱。                                                 
                                                                             
  比如：                                                                     
  - 如果你是独生子女家庭，"兄弟的孩子"这条规则对你就没用                     
  - 如果你父母都是独生子女，"父母的兄弟姐妹的孩子"这条规则对你也没用         
                                                                             
  在模型中：                                                                 
  - 头实体的embedding编码了它的"类型信息"（比如某个实体可能更常出现在家族关系中）
  - 关系embedding编码了"要找什么"                                            
  - 把这两个信息结合起来，动态给每条规则打分                                 
                                                                             
  技术细节（非代码）                                                         
                                                                             
  输入：                                                                     
  - 头实体Alice的embedding：一个2000维向量                                   
  - 关系aunt的embedding：一个2000维向量                                      
  - 所有候选规则的embedding：比如5条规则，每条2000维                         
                                                                             
  处理流程：                                                                 
  1. 把头实体和关系拼接起来 → 4000维的"查询向量"                             
  2. 把查询向量和每条规则的embedding都拼接 → 6000维                          
  3. 通过一个小神经网络（两层MLP）把6000维压缩到1个数字（注意力分数）        
  4. 这个分数在0-1之间（用Sigmoid激活），表示"这条规则对当前查询的重要性"    
  5. 用这个分数去加权规则的特征                                              
                                                                             
  效果预期：                                                                 
  - 对于不同的(h,r)查询，模型会自动学会"哪些规则更适合这个查询"              
  - 训练时通过反向传播自动学习这种关联性

  方案2：Path Diversity-Aware Scoring（路径多样性感知打分）                  
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：模型只统计"有多少条路径"，但不关心"这些路径是不是都一样"。       
                                                                             
  改进思路：区分路径数量（quantity）和路径多样性（diversity）。              
                                                                             
  具体例子                                                                   
                                                                             
  还是预测：(Alice, aunt, ?)                                                 
                                                                             
  通过规则 mother ∧ sister → aunt 进行grounding：                            
                                                                             
  场景A：低多样性                                                            
  - 路径1：Alice → mother → Mary → sister → Susan                            
  - 路径2：Alice → mother → Mary → sister → Susan                            
  - 路径3：Alice → mother → Mary → sister → Susan                            
  （3条路径，但都经过同一个中间节点Mary）                                    
                                                                             
  场景B：高多样性                                                            
  - 路径1：Alice → mother → Mary → sister → Susan                            
  - 路径2：Alice → mother → Jane → sister → Linda                            
  - 路径3：Alice → mother → Kate → sister → Emily                            
  （3条路径，经过3个不同的中间节点）                                         
                                                                             
  当前方法的问题：                                                           
  场景A和场景B的grounding count都是3，模型给出的分数一样。                   
                                                                             
  应该怎么样：                                                               
  场景B更可靠！因为：                                                        
  - 场景A：可能只是Mary这个节点的数据很完整，重复计数了                      
  - 场景B：有3个独立的证据链，更说明Susan、Linda、Emily都是Alice的aunt       
                                                                             
  实际意义的类比                                                             
                                                                             
  信息论的角度：                                                             
  - 3个人都告诉你"今天要下雨" → 如果这3个人都是从同一个天气预报看到的，其实只是1份证据
  - 3个人都告诉你"今天要下雨" → 如果这3个人分别是气象局、看云的农民、刚从外面回来的人，这是3份独立证据，可信度更高
                                                                             
  在知识图谱中：                                                             
  - 10条路径都经过同一个中间实体 → 可能是数据偏差                            
  - 10条路径经过10个不同的中间实体 → 说明这个预测被多方面证实                
                                                                             
  怎么计算多样性？                                                           
                                                                             
  基本思路：统计路径经过的不同中间节点数量                                   
                                                                             
  比如规则 r1 ∧ r2 → r3（两跳）：                                            
                                                                             
  Alice的查询：                                                              
  - 第一跳后到达：{Mary, Jane, Kate}（3个不同节点）                          
  - 第二跳后到达：{Susan}（都指向Susan）                                     
  - Count = 3（3条路径）                                                     
  - Diversity = 3个不同的第一跳节点                                          
                                                                             
  Bob的查询：                                                                
  - 第一跳后到达：{Mary, Mary, Mary}（只有1个节点）                          
  - 第二跳后到达：{Susan}                                                    
  - Count = 3                                                                
  - Diversity = 1个不同的第一跳节点                                          
                                                                             
  最终打分：                                                                 
  - Alice的Susan：score = count × (1 + 0.5 × diversity) = 3 × (1 + 0.5 × 3) = 7.5
  - Bob的Susan：score = 3 × (1 + 0.5 × 1) = 4.5                              
                                                                             
  结果：Alice的预测更可信                                                    
                                                                             
  为什么在Kinship上可能有效？                                                
                                                                             
  Kinship数据集特点：                                                        
  - 家族关系有很强的结构性                                                   
  - 同一个家族里，某些中心节点（比如祖父母）会被反复经过                     
  - 真正的家族关系应该有多条独立的证据链                                     
                                                                             
  举例：                                                                     
  如果你要证明"Charlie是Alice的cousin"：                                     
  - 弱证据：都是通过Grandma这一个节点连接                                    
  - 强证据：可以通过Grandma、Grandpa、Uncle三条不同的路径证明

  方案3：Hierarchical Rule Aggregation（分层规则聚合）                       
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：所有规则的信息被"一锅煮"——用简单平均池化（mean pooling）混在一起。
                                                                             
  改进思路：把规则按质量分层，先在层内聚合，再在层间聚合，类似"先组内讨论，再全班投票"。
                                                                             
  具体例子                                                                   
                                                                             
  假设要预测 (Alice, aunt, ?)，有10条规则：                                  
                                                                             
  规则质量（预训练阶段学到的confidence）：                                   
  - 高质量规则（5条）：confidence > 0.7                                      
    - 规则1：mother ∧ sister → aunt，confidence=0.9                          
    - 规则2：father ∧ sister → aunt，confidence=0.85                         
    - 规则3：parent ∧ sister → aunt，confidence=0.8                          
    - ...                                                                    
  - 中等质量规则（3条）：0.4 < confidence < 0.7                              
    - 规则6：mother ∧ sibling ∧ female → aunt，confidence=0.6                
    - ...                                                                    
  - 低质量规则（2条）：confidence < 0.4                                      
    - 规则9：一些很长的、不常用的规则，confidence=0.3                        
                                                                             
  当前方法：                                                                 
  把10条规则grounding后的特征直接平均：                                      
  final_feature = (feature1 + feature2 + ... + feature10) / 10               
                                                                             
  问题：                                                                     
  - 低质量规则的噪声会稀释高质量规则的信号                                   
  - 就像班级投票，让从不参加讨论的同学和积极分子有同样的投票权               
                                                                             
  Hierarchical的做法                                                         
                                                                             
  第一步：层内聚合                                                           
  - 高质量组：内部聚合5条规则 → 得到 high_quality_feature                    
  - 中等质量组：内部聚合3条规则 → 得到 medium_quality_feature                
  - 低质量组：内部聚合2条规则 → 得到 low_quality_feature                     
                                                                             
  第二步：层间attention                                                      
  模型动态决定每一层的权重：                                                 
  - 对于这个特定的查询(Alice, aunt)，模型可能学到：                          
    - 高质量组权重：0.7                                                      
    - 中等质量组权重：0.25                                                   
    - 低质量组权重：0.05                                                     
                                                                             
  第三步：加权求和                                                           
  final = 0.7 × high_quality_feature +                                       
          0.25 × medium_quality_feature +                                    
          0.05 × low_quality_feature                                         
                                                                             
  为什么有效？                                                               
                                                                             
  类比：专家系统                                                             
                                                                             
  假设你生病了，要决定吃什么药：                                             
  - 方法1（当前）：找10个人（包括医生、护士、路人）问意见，把10个意见简单平均
  - 方法2（Hierarchical）：                                                  
    - 先把10个人分组：专家组（3个医生）、专业组（4个护士）、普通组（3个路人）
    - 每组内部先讨论得出组意见                                               
    - 然后给专家组更高的权重（0.6）、专业组中等权重（0.3）、普通组低权重（0.1）
    - 最终决策 = 0.6×专家意见 + 0.3×专业意见 + 0.1×路人意见                  
                                                                             
  方法2显然更合理。                                                          
                                                                             
  在规则推理中的体现                                                         
                                                                             
  为什么不同质量的规则要分开处理？                                           
                                                                             
  1. 信息粒度不同：                                                          
    - 高质量规则：简单、直接、被大量数据验证                                 
        - mother ∧ sister → aunt（几乎总是对的）                             
    - 低质量规则：复杂、特殊情况、数据稀疏                                   
        - mother ∧ sibling ∧ female ∧ older → aunt（可能只适用于某些特殊文化背景）
  2. 噪声水平不同：                                                          
    - 高质量规则即使grounding count少，也可能很重要                          
    - 低质量规则即使grounding count多，也可能是噪声                          
  3. 需要不同的处理策略：                                                    
    - 高质量规则：应该保留细节，直接传递信息                                 
    - 低质量规则：应该强力平滑，抑制噪声                                     
                                                                             
  分层的额外好处                                                             
                                                                             
  可解释性：                                                                 
  训练完后，你可以分析：                                                     
  - 对于"aunt"关系，模型主要依赖高质量规则（权重0.7）                        
  - 对于"cousin"关系，模型可能需要中等质量规则（权重0.5）                    
    - 因为cousin关系更复杂，没有那么直接的规则                               
                                                                             
  鲁棒性：                                                                   
  - 如果某一层的规则全都没有grounding（count=0），不会让整个预测崩溃         
  - 其他层还能提供信息                                                       
                                                                             
  ---                                                                        
  三个方案的关系与组合                                                       
                                                                             
  互补性分析                                                                 
                                                                             
  方案1（Query-Conditioned）：                                               
  - 解决："哪些规则适合这个查询"                                             
  - 作用位置：规则选择阶段                                                   
  - 输入依赖：(h, r)的embedding                                              
                                                                             
  方案2（Path Diversity）：                                                  
  - 解决："路径证据的质量如何"                                               
  - 作用位置：grounding计数阶段                                              
  - 输入依赖：图结构的遍历过程                                               
                                                                             
  方案3（Hierarchical）：                                                    
  - 解决："如何合理聚合不同质量的信息"                                       
  - 作用位置：特征聚合阶段                                                   
  - 输入依赖：规则的预训练confidence                                         
                                                                             
  可以组合吗？                                                               
                                                                             
  完全可以！三个方案作用在不同阶段：                                         
                                                                             
  1. Grounding阶段（方案2）：                                                
    - 在图上遍历，统计路径的count和diversity                                 
    - 输出：每条规则的 (count, diversity) 元组                               
  2. 规则权重计算（方案1）：                                                 
    - 根据当前查询(h,r)，计算每条规则的attention权重                         
    - 输出：每条规则的query-specific权重                                     
  3. 特征聚合（方案3）：                                                     
    - 把规则分层，每层内部聚合，层间weighted sum                             
    - 使用前两步的信息：count×diversity作为重要性，attention作为相关性       
                                                                             
  组合后的流程：                                                             
  输入：(Alice, aunt, ?)                                                     
                                                                             
  → [Grounding] 10条规则各自遍历图                                           
    规则1: count=5, diversity=3                                              
    规则2: count=3, diversity=3                                              
    规则3: count=8, diversity=2                                              
    ...                                                                      
                                                                             
  → [Query-Conditioned] 计算Alice+aunt对每条规则的attention                  
    规则1: attention=0.9                                                     
    规则2: attention=0.3                                                     
    规则3: attention=0.7                                                     
    ...                                                                      
                                                                             
  → [Hierarchical] 分层聚合                                                  
    高质量层（规则1,2,3）:                                                   
      weighted_score = 5×3×0.9 + 3×3×0.3 + 8×2×0.7 = ...                     
    中质量层: ...                                                            
    低质量层: ...                                                            
                                                                             
    最终：high_layer×0.7 + mid_layer×0.2 + low_layer×0.1                     
                                                                             
  → 输出：候选实体的最终分数

  为什么这些方案有理有据？                                                   
                                                                             
  理论基础                                                                   
                                                                             
  方案1：注意力机制                                                          
  - 来源：Transformer、BERT等NLP模型的核心                                   
  - 核心insight：不同的query应该关注不同的信息                               
  - 在KG中的应用：GAATs (Graph Attention Networks)已证明有效                 
                                                                             
  方案2：信息论                                                              
  - 来源：香农信息论、集成学习中的diversity                                  
  - 核心insight：独立证据比重复证据更有价值                                  
  - 在KG中的应用：路径排序（Path Ranking Algorithm）考虑路径独立性           
                                                                             
  方案3：层次化表示学习                                                      
  - 来源：Hierarchical Attention Networks (HAN)、Mixture of Experts          
  - 核心insight：不同质量的信息源需要差异化处理                              
  - 在KG中的应用：多源知识融合、规则挖掘中的置信度分层                       
                                                                             
  为什么在Kinship上应该有效？                                                
                                                                             
  数据集特点决定的：                                                         
                                                                             
  1. 实体数少（104个）：                                                     
    - 每个实体的特征很重要 → 方案1有用（query-specific）                     
    - 图的连通性强，容易出现重复路径 → 方案2有用（diversity）                
  2. 关系语义强（家族关系）：                                                
    - 规则质量差异大（"父母的兄弟姐妹" vs "父母的配偶的兄弟的配偶"）         
    - → 方案3有用（分层处理）                                                
  3. 规则数量多（10000条）：                                                 
    - 很多规则是冗余或噪声 → 需要更精细的选择机制                            
    - → 所有方案都有用

  方案4：Query-Conditioned Fusion Gate（查询感知的融合门控，建议优先做）      

  核心动机                                                                   

  你当前最终推理通常是：                                                     
  - grounding logits（规则/grounding得到的分数）                              
  - KGE score（RotatE等嵌入模型得到的分数）                                   
  - 最后用固定超参数 alpha 融合：                                            
    final_logits = grounding_logits + alpha * kge_score                      

  问题：固定 alpha 对所有查询(h,r)一刀切。                                    
  - 有些关系/实体对规则推理更可靠（应更信任 grounding）                        
  - 有些关系更偏语义/嵌入泛化（应更信任 KGE）                                 
  - 固定 alpha 会把“本来应该规则主导的查询”被 KGE 淹没，或相反                

  改进思路                                                                   

  学一个 query-specific 的融合权重，让模型对不同查询动态决定“更信谁”：        
  - 用门控 g(h,r)∈(0,1) 控制两者占比                                          
  - 更推荐用 sigmoid 输出，稳定且易解释                                      

  两种等价写法（推荐第1种）                                                  

  1) convex 组合（显式在[0,1]内归一）：                                       
     g = sigmoid( MLP([h_emb, r_emb]) )                                      
     final = g * grounding_logits + (1 - g) * kge_score_map                  

     说明：kge_score_map 是与 grounding_logits 对齐后的实体打分（维度一致）。  

  2) alpha(h,r) 形式（与现有实现兼容）：                                      
     alpha = softplus( MLP([h_emb, r_emb]) )  ≥ 0                            
     final = grounding_logits + alpha * kge_score_map                        

     说明：softplus 保证 alpha 非负，避免训练初期出现符号翻转。                

  为什么这比“继续打磨 grounding 内部聚合”更有效                              

  你的最终指标往往看的是 grounding + KGE 的融合（比如 test_kge）。            
  如果 KGE 项很强，grounding 内部的改动（方案1/3）经常被 alpha*KGE 淹没，      
  体现在 MRR 上只剩千分级波动。                                               
  Query-conditioned gate 直接作用在融合处，能显著改变最终排序，收益更可能稳定。 

  具体实现建议（对应你当前代码结构）                                          

  - 在模型里新增一个 FusionGate：                                            
    输入：h_emb（2d维） + r_emb（d维） → 拼接 3d                            
    输出：g 或 alpha（标量或按关系类型输出）                                  

  - 推理时用 gate 融合：                                                     
    grounding_logits：来自 grounding forward                                 
    kge_score_map：来自 compute_g_KGE（注意正/反向与维度对齐）                
    final_logits：按上面的公式融合                                            

  关键提醒（对应你现在“加门控反而更差”的现象）                               
  - 如果把 gate 放进 grounding 训练里一起学，gate 很容易走捷径：              
    直接把 g→0（或 alpha→alpha_max）让 KGE 主导，导致 grounding 学不到东西，MRR 反而下降。
  - 更稳的做法是先做“推理/校准阶段 gate”：grounding 训练完冻结；gate 只在 test_kge 融合时用。

	  推理阶段动态 alpha 的两种做法（不改 grounding 训练）                        
	  A. Heuristic gate（最快验证、0 训练）                                      
	    - 用 grounding 置信度特征（top1-top2 margin、entropy、grounding 覆盖率等）映射到 alpha∈[alpha_min, alpha_max]
	    - grounding 越不确定 → alpha 越大（更信 KGE）；grounding 越确定 → alpha 越小
	  B. Calibration gate（更可能有收益、单独训练 gate）                          
	    - 冻结 grounding+KGE，只训练一个小的 gate MLP：输入 [h_emb, r_emb] 或加上简单的 grounding 统计特征，输出 g(h,r) 或 alpha(h,r)
	    - 训练数据：沿用训练集/valid 集的 (h,r,t) 三元组；对每个 (h,r)，用当前的 grounding_logits、kge_score 先算出融合前的实体打分，再加上 gate 输出，得到 final_logits
	    - 损失函数：在 final_logits 上，对“真尾实体 t 和若干负采样尾实体”做 softmax 交叉熵，让 gate 学会“在什么情况下应该更信 grounding / 更信 KGE”
	    - 训练方式：  
	      1）第一阶段只训原模型（不带 gate），拿到固定的 grounding+KGE；  
	      2）第二阶段把原模型参数全部冻结，只迭代若干 epoch 更新 gate 参数（类似于后验校准 / re-ranking）  
	    - 优点：不会破坏已经训练好的 grounding/KGE，只是在推理层面做一个 learnable 的 “融合校准”，通常比纯 heuristic 的调节更稳定
        更精确一点分三步看：

  1. 先把动态 alpha 模型（gate）训练好
      - 输入：每个查询的 (h,r)（用 h_emb, r_emb 表示），可选再拼一点 grounding
        的统计特征。
      - 输出：一标量 alpha(h,r) 或 g(h,r)。
      - 训练时：
          - 冻结现在的 grounding + KGE；
          - 对训练/valid 里的 (h,r,t)，用当前模型算出 grounding_logits 和
            kge_score；
          - 把 (h_emb,r_emb,…) 喂进 gate → 得到 alpha(h,r)；
          - 用 final_logits = grounding_logits + alpha(h,r)*kge_score（或
            convex 版本）在“真 t + 负采样 t”上做 cross-entropy，只更新 gate 参
            数。
  2. 训练完 gate 以后固定它的参数
  3. 推理阶段（test/test_kge）
      - 对测试集中每一个查询 (h,r, ?)：
          - 先用当前 RulE 算 grounding_logits 和 kge_score；
          - 再把 (h,r) 通过训练好的 gate，得到这个查询自己的 alpha(h,r)；
          - 用 final_logits = grounding_logits + alpha(h,r)*kge_score 排序所有
            候选 tail。
      - 所以：不同查询有不同的 alpha(h,r)，但同一个查询下所有候选 tail 共用这
        一个 alpha（如果你以后想做到 (h,r,t) 粒度，也可以再往下细化）。

  - 诊断与可解释性：                                                         
    统计不同关系 r 的平均 g(h,r) 或 alpha(h,r)，能直观看出哪些关系偏规则/偏嵌入。

     1. Gate 的基本架构（模型长什么样）

  目标：学一个标量函数
  [
  \alpha(h,r) \quad\text{或}\quad g(h,r)\in(0,1)
  ]
  只依赖当前查询 (h,r)（可额外加一点 grounding 统计特征）。

  一个很自然的架构：

  - 输入（一条查询对应一条输入向量）：
      - h_emb：头实体 embedding，来自你现在的 RulE.get_query_embeddings(all_h,
        all_r)，维度 2d。
      - r_emb：关系 embedding，同上，维度 d。
      - 可选：简单的 grounding 特征（标量），例如：
          - margin_ratio：top1-top2 差值 / |top1|
          - entropy：top-k softmax 的熵
          - coverage：有 grounding 支持的候选实体占比
      - 最终拼成一个向量：[h_emb, r_emb, margin_ratio, entropy, coverage]，维
        度大约是 3d + 3。
  - 网络结构（Gate MLP）：
      - 例如两层 MLP：
          - Linear(3d+3 → 256) + ReLU + Dropout(0.1)
          - Linear(256 → 1)
      - 输出一个标量 z(h,r)，再做约束得到 alpha/gate：
          - 如果走 convex gate：
              - g(h,r) = sigmoid(z) ∈ (0,1)
              - final_logits = g * grounding_logits + (1 - g) * kge_score
          - 如果走 alpha 形式（和你现在超参 alpha 对齐）：
              - alpha(h,r) = alpha_min + (alpha_max - alpha_min) * sigmoid(z)
              - 确保 alpha(h,r) ∈ [alpha_min, alpha_max]，不会乱飞。
  - 关键点：这个 Gate 模型是一个很小的网络，参数量远小于 RulE 本身，训练成本很
    低。

  ———

  2. 训练动态 alpha 的目标函数（怎么学会“该信谁”）

  训练阶段我们 冻结整套 RulE（grounding+KGE），只更新 gate 的参数，让 gate 学
  会“在什么情况下更信 grounding / 更信 KGE”。

  对于每个训练/验证三元组 (h,r,t)：

  1. 用已经训练好的原模型，算出：
      - grounding_logits(h,r, :)：规则推理得分（对所有实体）。
      - kge_score(h,r, :)：KGE 得分（对所有实体）。
  2. 用 gate MLP 计算该查询的权重：
      - 把 (h_emb, r_emb, margin_ratio, entropy, coverage) 输入 gate → 得到
        alpha(h,r) 或 g(h,r)。
  3. 融合得到最终打分：
      - final_logits = grounding_logits + alpha(h,r) * kge_score
        或
      - final_logits = g(h,r) * grounding_logits + (1 - g(h,r)) * kge_score
  4. 为了定义一个可微的 loss，我们抽一小撮侯选尾实体：
      - 取 真尾实体 t；
      - 采样若干负尾实体 {t_1^-, ..., t_k^-}；
      - 在这 k+1 个实体上截取 final_logits，做 softmax：
        [
        p(t | h,r) = \frac{\exp(f(h,r,t))}{\exp(f(h,r,t)) + \sum_j
        \exp(f(h,r,t_j^-))}
        ]
      - loss 就是标准交叉熵：
        [
        \mathcal{L} = -\log p(t | h,r)
        ]
  5. 对 gate 参数做反向传播（原模型冻结不动），让 gate 学会：
      - 当 grounding 本身就能把真 t 排得很前时，alpha 要偏小（多信
        grounding）；
      - 当 grounding 很不确定 / 排名差时，alpha 要偏大（多信 KGE）。

  ———

  3. 实际训练流程（两阶段）

  整体建议你按“两阶段训练”来做，避免 gate 把 RulE 原模型带偏：

  1. 阶段 1：正常训练现在的 RulE（你已经在做的）
      - 预训练：不确定性 + RotatE；
      - grounding 阶段：只用规则 logits 训练；
      - 测试时用固定超参 alpha 做 grounding + alpha*KGE，得到一个 baseline。
  2. 阶段 2：冻结 RulE，只训 Gate（Calibration）
      - 冻结 RulE 所有参数；
      - 新建一个 GateMLP 模块，只包含少量线性层；
      - 用上面的 (h,r,t, negatives) + cross-entropy 训练 Gate：
          - 建议用 训练集 + 一部分 valid 集；
          - 在剩余的 valid 上 early stopping，看 test_kge 风格的 MRR 是否提
            升。
  3. 推理阶段（真正 test/test_kge）
      - 对每个测试查询 (h,r, ?)：
          - 用 RulE 算出 grounding_logits 和 kge_score；
          - 用训练好的 Gate 算 alpha(h,r) 或 g(h,r)；
          - 融合出 final_logits 排序所有尾实体；
      - 这样就实现了你说的：“训练好一个动态 alpha 模型，推理时每个查询都有自己
        的 alpha”。

  ———

  4. 为什么这样更靠谱

  - Gate 的学习目标是：直接提高最终 grounding + KGE 的区分度，比手写 heuristic
    映射更贴数据。
  - 又因为我们是 在原模型训练完之后、单独校准 gate，不会破坏你已经训练好的
    grounding / 不确定性建模，只是在推理层上调一个“融合权重”。
  - 你可以很直观地看统计：
      - 不同关系 r 上 alpha(h,r) 的均值 / 方差；
      - 哪些关系更偏规则，哪些关系 gate 学出来更偏 KGE。
