方案1：Query-Conditioned Rule Attention（查询感知的规则注意力）            
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：现在的模型对所有规则一视同仁。比如你要预测 (张三, 配偶, ?) 时，所有规则头是"配偶"的规则都会被同等对待。
                                                                             
  改进思路：不同的查询应该对不同的规则有不同的关注度。                       
                                                                             
  具体例子                                                                   
                                                                             
  假设你在Kinship数据集中要预测：                                            
  - 查询1：(Alice, aunt, ?)  // Alice的姨妈是谁？                            
  - 查询2：(Bob, aunt, ?)    // Bob的姨妈是谁？                              
                                                                             
  数据库里有两条规则：                                                       
  - 规则A：mother ∧ sister → aunt（妈妈的姐妹是姨妈）                        
  - 规则B：father ∧ sister → aunt（爸爸的姐妹也是姨妈）                      
                                                                             
  当前方法的问题：                                                           
  两条规则对所有查询的权重都一样。但实际上：                                 
  - 如果Alice的数据里有很多"mother"关系的记录，规则A应该更重要               
  - 如果Bob的数据里只有"father"关系，那规则B应该更重要                       
                                                                             
  Query-Conditioned的做法：                                                  
  模型会看查询中的头实体（Alice或Bob）的embedding，结合关系（aunt）的embedding，动态决定：
  - 对Alice的查询：规则A权重=0.8，规则B权重=0.3                              
  - 对Bob的查询：规则A权重=0.2，规则B权重=0.9                                
                                                                             
  为什么有效？                                                               
                                                                             
  类比到实际生活：                                                           
  你要找"谁是我的亲戚"这个问题，你会根据：                                   
  - 我自己的家庭背景（头实体特征）                                           
  - 我要找的是什么关系（关系类型）                                           
  来决定哪些推理路径更靠谱。                                                 
                                                                             
  比如：                                                                     
  - 如果你是独生子女家庭，"兄弟的孩子"这条规则对你就没用                     
  - 如果你父母都是独生子女，"父母的兄弟姐妹的孩子"这条规则对你也没用         
                                                                             
  在模型中：                                                                 
  - 头实体的embedding编码了它的"类型信息"（比如某个实体可能更常出现在家族关系中）
  - 关系embedding编码了"要找什么"                                            
  - 把这两个信息结合起来，动态给每条规则打分                                 
                                                                             
  技术细节（非代码）                                                         
                                                                             
  输入：                                                                     
  - 头实体Alice的embedding：一个2000维向量                                   
  - 关系aunt的embedding：一个2000维向量                                      
  - 所有候选规则的embedding：比如5条规则，每条2000维                         
                                                                             
  处理流程：                                                                 
  1. 把头实体和关系拼接起来 → 4000维的"查询向量"                             
  2. 把查询向量和每条规则的embedding都拼接 → 6000维                          
  3. 通过一个小神经网络（两层MLP）把6000维压缩到1个数字（注意力分数）        
  4. 这个分数在0-1之间（用Sigmoid激活），表示"这条规则对当前查询的重要性"    
  5. 用这个分数去加权规则的特征                                              
                                                                             
  效果预期：                                                                 
  - 对于不同的(h,r)查询，模型会自动学会"哪些规则更适合这个查询"              
  - 训练时通过反向传播自动学习这种关联性                                     
                                                                             
  ---                                                                        
  方案2：Path Diversity-Aware Scoring（路径多样性感知打分）                  
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：模型只统计"有多少条路径"，但不关心"这些路径是不是都一样"。       
                                                                             
  改进思路：区分路径数量（quantity）和路径多样性（diversity）。              
                                                                             
  具体例子                                                                   
                                                                             
  还是预测：(Alice, aunt, ?)                                                 
                                                                             
  通过规则 mother ∧ sister → aunt 进行grounding：                            
                                                                             
  场景A：低多样性                                                            
  - 路径1：Alice → mother → Mary → sister → Susan                            
  - 路径2：Alice → mother → Mary → sister → Susan                            
  - 路径3：Alice → mother → Mary → sister → Susan                            
  （3条路径，但都经过同一个中间节点Mary）                                    
                                                                             
  场景B：高多样性                                                            
  - 路径1：Alice → mother → Mary → sister → Susan                            
  - 路径2：Alice → mother → Jane → sister → Linda                            
  - 路径3：Alice → mother → Kate → sister → Emily                            
  （3条路径，经过3个不同的中间节点）                                         
                                                                             
  当前方法的问题：                                                           
  场景A和场景B的grounding count都是3，模型给出的分数一样。                   
                                                                             
  应该怎么样：                                                               
  场景B更可靠！因为：                                                        
  - 场景A：可能只是Mary这个节点的数据很完整，重复计数了                      
  - 场景B：有3个独立的证据链，更说明Susan、Linda、Emily都是Alice的aunt       
                                                                             
  实际意义的类比                                                             
                                                                             
  信息论的角度：                                                             
  - 3个人都告诉你"今天要下雨" → 如果这3个人都是从同一个天气预报看到的，其实只是1份证据
  - 3个人都告诉你"今天要下雨" → 如果这3个人分别是气象局、看云的农民、刚从外面回来的人，这是3份独立证据，可信度更高
                                                                             
  在知识图谱中：                                                             
  - 10条路径都经过同一个中间实体 → 可能是数据偏差                            
  - 10条路径经过10个不同的中间实体 → 说明这个预测被多方面证实                
                                                                             
  怎么计算多样性？                                                           
                                                                             
  基本思路：统计路径经过的不同中间节点数量                                   
                                                                             
  比如规则 r1 ∧ r2 → r3（两跳）：                                            
                                                                             
  Alice的查询：                                                              
  - 第一跳后到达：{Mary, Jane, Kate}（3个不同节点）                          
  - 第二跳后到达：{Susan}（都指向Susan）                                     
  - Count = 3（3条路径）                                                     
  - Diversity = 3个不同的第一跳节点                                          
                                                                             
  Bob的查询：                                                                
  - 第一跳后到达：{Mary, Mary, Mary}（只有1个节点）                          
  - 第二跳后到达：{Susan}                                                    
  - Count = 3                                                                
  - Diversity = 1个不同的第一跳节点                                          
                                                                             
  最终打分：                                                                 
  - Alice的Susan：score = count × (1 + 0.5 × diversity) = 3 × (1 + 0.5 × 3) = 7.5
  - Bob的Susan：score = 3 × (1 + 0.5 × 1) = 4.5                              
                                                                             
  结果：Alice的预测更可信                                                    
                                                                             
  为什么在Kinship上可能有效？                                                
                                                                             
  Kinship数据集特点：                                                        
  - 家族关系有很强的结构性                                                   
  - 同一个家族里，某些中心节点（比如祖父母）会被反复经过                     
  - 真正的家族关系应该有多条独立的证据链                                     
                                                                             
  举例：                                                                     
  如果你要证明"Charlie是Alice的cousin"：                                     
  - 弱证据：都是通过Grandma这一个节点连接                                    
  - 强证据：可以通过Grandma、Grandpa、Uncle三条不同的路径证明

  方案3：Hierarchical Rule Aggregation（分层规则聚合）                       
                                                                             
  核心思想                                                                   
                                                                             
  当前问题：所有规则的信息被"一锅煮"——用简单平均池化（mean pooling）混在一起。
                                                                             
  改进思路：把规则按质量分层，先在层内聚合，再在层间聚合，类似"先组内讨论，再全班投票"。
                                                                             
  具体例子                                                                   
                                                                             
  假设要预测 (Alice, aunt, ?)，有10条规则：                                  
                                                                             
  规则质量（预训练阶段学到的confidence）：                                   
  - 高质量规则（5条）：confidence > 0.7                                      
    - 规则1：mother ∧ sister → aunt，confidence=0.9                          
    - 规则2：father ∧ sister → aunt，confidence=0.85                         
    - 规则3：parent ∧ sister → aunt，confidence=0.8                          
    - ...                                                                    
  - 中等质量规则（3条）：0.4 < confidence < 0.7                              
    - 规则6：mother ∧ sibling ∧ female → aunt，confidence=0.6                
    - ...                                                                    
  - 低质量规则（2条）：confidence < 0.4                                      
    - 规则9：一些很长的、不常用的规则，confidence=0.3                        
                                                                             
  当前方法：                                                                 
  把10条规则grounding后的特征直接平均：                                      
  final_feature = (feature1 + feature2 + ... + feature10) / 10               
                                                                             
  问题：                                                                     
  - 低质量规则的噪声会稀释高质量规则的信号                                   
  - 就像班级投票，让从不参加讨论的同学和积极分子有同样的投票权               
                                                                             
  Hierarchical的做法                                                         
                                                                             
  第一步：层内聚合                                                           
  - 高质量组：内部聚合5条规则 → 得到 high_quality_feature                    
  - 中等质量组：内部聚合3条规则 → 得到 medium_quality_feature                
  - 低质量组：内部聚合2条规则 → 得到 low_quality_feature                     
                                                                             
  第二步：层间attention                                                      
  模型动态决定每一层的权重：                                                 
  - 对于这个特定的查询(Alice, aunt)，模型可能学到：                          
    - 高质量组权重：0.7                                                      
    - 中等质量组权重：0.25                                                   
    - 低质量组权重：0.05                                                     
                                                                             
  第三步：加权求和                                                           
  final = 0.7 × high_quality_feature +                                       
          0.25 × medium_quality_feature +                                    
          0.05 × low_quality_feature                                         
                                                                             
  为什么有效？                                                               
                                                                             
  类比：专家系统                                                             
                                                                             
  假设你生病了，要决定吃什么药：                                             
  - 方法1（当前）：找10个人（包括医生、护士、路人）问意见，把10个意见简单平均
  - 方法2（Hierarchical）：                                                  
    - 先把10个人分组：专家组（3个医生）、专业组（4个护士）、普通组（3个路人）
    - 每组内部先讨论得出组意见                                               
    - 然后给专家组更高的权重（0.6）、专业组中等权重（0.3）、普通组低权重（0.1）
    - 最终决策 = 0.6×专家意见 + 0.3×专业意见 + 0.1×路人意见                  
                                                                             
  方法2显然更合理。                                                          
                                                                             
  在规则推理中的体现                                                         
                                                                             
  为什么不同质量的规则要分开处理？                                           
                                                                             
  1. 信息粒度不同：                                                          
    - 高质量规则：简单、直接、被大量数据验证                                 
        - mother ∧ sister → aunt（几乎总是对的）                             
    - 低质量规则：复杂、特殊情况、数据稀疏                                   
        - mother ∧ sibling ∧ female ∧ older → aunt（可能只适用于某些特殊文化背景）
  2. 噪声水平不同：                                                          
    - 高质量规则即使grounding count少，也可能很重要                          
    - 低质量规则即使grounding count多，也可能是噪声                          
  3. 需要不同的处理策略：                                                    
    - 高质量规则：应该保留细节，直接传递信息                                 
    - 低质量规则：应该强力平滑，抑制噪声                                     
                                                                             
  分层的额外好处                                                             
                                                                             
  可解释性：                                                                 
  训练完后，你可以分析：                                                     
  - 对于"aunt"关系，模型主要依赖高质量规则（权重0.7）                        
  - 对于"cousin"关系，模型可能需要中等质量规则（权重0.5）                    
    - 因为cousin关系更复杂，没有那么直接的规则                               
                                                                             
  鲁棒性：                                                                   
  - 如果某一层的规则全都没有grounding（count=0），不会让整个预测崩溃         
  - 其他层还能提供信息                                                       
                                                                             
  ---                                                                        
  三个方案的关系与组合                                                       
                                                                             
  互补性分析                                                                 
                                                                             
  方案1（Query-Conditioned）：                                               
  - 解决："哪些规则适合这个查询"                                             
  - 作用位置：规则选择阶段                                                   
  - 输入依赖：(h, r)的embedding                                              
                                                                             
  方案2（Path Diversity）：                                                  
  - 解决："路径证据的质量如何"                                               
  - 作用位置：grounding计数阶段                                              
  - 输入依赖：图结构的遍历过程                                               
                                                                             
  方案3（Hierarchical）：                                                    
  - 解决："如何合理聚合不同质量的信息"                                       
  - 作用位置：特征聚合阶段                                                   
  - 输入依赖：规则的预训练confidence                                         
                                                                             
  可以组合吗？                                                               
                                                                             
  完全可以！三个方案作用在不同阶段：                                         
                                                                             
  1. Grounding阶段（方案2）：                                                
    - 在图上遍历，统计路径的count和diversity                                 
    - 输出：每条规则的 (count, diversity) 元组                               
  2. 规则权重计算（方案1）：                                                 
    - 根据当前查询(h,r)，计算每条规则的attention权重                         
    - 输出：每条规则的query-specific权重                                     
  3. 特征聚合（方案3）：                                                     
    - 把规则分层，每层内部聚合，层间weighted sum                             
    - 使用前两步的信息：count×diversity作为重要性，attention作为相关性       
                                                                             
  组合后的流程：                                                             
  输入：(Alice, aunt, ?)                                                     
                                                                             
  → [Grounding] 10条规则各自遍历图                                           
    规则1: count=5, diversity=3                                              
    规则2: count=3, diversity=3                                              
    规则3: count=8, diversity=2                                              
    ...                                                                      
                                                                             
  → [Query-Conditioned] 计算Alice+aunt对每条规则的attention                  
    规则1: attention=0.9                                                     
    规则2: attention=0.3                                                     
    规则3: attention=0.7                                                     
    ...                                                                      
                                                                             
  → [Hierarchical] 分层聚合                                                  
    高质量层（规则1,2,3）:                                                   
      weighted_score = 5×3×0.9 + 3×3×0.3 + 8×2×0.7 = ...                     
    中质量层: ...                                                            
    低质量层: ...                                                            
                                                                             
    最终：high_layer×0.7 + mid_layer×0.2 + low_layer×0.1                     
                                                                             
  → 输出：候选实体的最终分数                                                 
                                                                             
  ---                                                                        
  为什么这些方案有理有据？                                                   
                                                                             
  理论基础                                                                   
                                                                             
  方案1：注意力机制                                                          
  - 来源：Transformer、BERT等NLP模型的核心                                   
  - 核心insight：不同的query应该关注不同的信息                               
  - 在KG中的应用：GAATs (Graph Attention Networks)已证明有效                 
                                                                             
  方案2：信息论                                                              
  - 来源：香农信息论、集成学习中的diversity                                  
  - 核心insight：独立证据比重复证据更有价值                                  
  - 在KG中的应用：路径排序（Path Ranking Algorithm）考虑路径独立性           
                                                                             
  方案3：层次化表示学习                                                      
  - 来源：Hierarchical Attention Networks (HAN)、Mixture of Experts          
  - 核心insight：不同质量的信息源需要差异化处理                              
  - 在KG中的应用：多源知识融合、规则挖掘中的置信度分层                       
                                                                             
  为什么在Kinship上应该有效？                                                
                                                                             
  数据集特点决定的：                                                         
                                                                             
  1. 实体数少（104个）：                                                     
    - 每个实体的特征很重要 → 方案1有用（query-specific）                     
    - 图的连通性强，容易出现重复路径 → 方案2有用（diversity）                
  2. 关系语义强（家族关系）：                                                
    - 规则质量差异大（"父母的兄弟姐妹" vs "父母的配偶的兄弟的配偶"）         
    - → 方案3有用（分层处理）                                                
  3. 规则数量多（10000条）：                                                 
    - 很多规则是冗余或噪声 → 需要更精细的选择机制                            
    - → 所有方案都有用

  ## 方案 1：Soft-Grounding（在“补全图”上跑规则）——最推荐

  ### 1.1 你现在的 grounding 是什么

  你现在每条规则体 r_body=[r1,r2,...,rk] 的 grounding，本质是在观
  测图上做离散可达/计数：图里没有这条边就断路，最后得到
  count_i(h→t)（src/model.py 里对每条规则调用 graph.grounding）。

  这会导致规则推理的核心短板：

  - 图里缺边（KG 不完备）→ 规则链路断掉 → 真实 tail 根本不会进入候
    选/支持度为 0。
  - 你再怎么调分数融合都救不了“断路”。

  ### 1.2 Soft-Grounding 的核心：把 KGE 变成“软边”，补全图的可达性

  把 KGE（RotatE）的打分视作“这条边存在的概率/置信度”。对任意三元
  组 (h,r,t) 定义：

  - p_kge(h,r,t) = sigmoid((s_kge(h,r,t) - b_r) / T_r)
    T_r 是温度，b_r 是偏置（都可以先用固定值，或按关系标定；但这不
    是动态 gate）

  然后定义一张“软补全图”：

  - 观测边：权重=1
  - 预测边：权重= η * p_kge（η 控制补全强度，0.1~1 之间）

  最终你的规则 grounding 不再是在 0/1 图上数路径，而是在带权图上算
  路径支持度：

  - 一条路径的权重 = 沿途边权的乘积（或 log-space 相加）
  - 多条路径汇总 = 求和 / Noisy-OR（两种都行）

  直观理解：KGE 只负责“把路接上”，规则负责“用结构解释”。

  ### 1.3 为什么这比 alpha/融合稳

  - 不是把两个 scorer 生硬加权，而是让规则推理在更完整的图上工作。
  - KGE 的作用变成结构层面的“补边”，不会出现你之前 gate 那种训练/
    推理分布不一致的问题。
  - 可解释：你可以统计多少命中来自观测边、多少命中依赖预测边。

  ### 1.4 怎么落地（关键是稀疏化，否则全连接爆）

  不能真的对所有 (h,r,t) 都加软边，必须稀疏化：

  - 对每个 (h,r) 只保留 KGE topB 的 tail（B=50~500），形成候选预测
    邻居 N̂_r(h)。
  - 预测边权 w(h,r,t)=η*p_kge(h,r,t) 只在这些 topB 上存在。

  这样你仍然是在稀疏邻接上做可微传播/计数。

  ### 1.5 在你现有结构里怎么插

  你现在的 pipeline 是：

  - 预训练得到 KGE embedding（RotatE）
  - grounding 阶段用 graph.grounding 得 count
  - rule_to_entity 聚合成每个 tail 的特征再打分

  Soft-Grounding 的插点就是把 graph.grounding(...) 从“离散邻接”换
  成“观测邻接 + 预测邻接”：

  - 对规则体每一步关系 rj，取观测邻居 N_rj(h) 与预测邻居 N̂_rj(h)
    的 union，并带权传播。
  - 输出的 count 变成 float 支持度（而不是 0/1 或整数计数），后面
    照常走。

  ### 1.6 你能看到的关键日志（证明它在起作用）

  - “断路率”下降：原来规则体第 j 步扩散后节点集合为空的比例。
  - 命中来源分解：正确 tail 的支持度里，预测边贡献占比。
  - 规则长度越长收益越明显（长链最怕缺边）。

## 核心想法（一句话）

  把 KGE（RotatE）当成“软边概率”，在规则体传播（grounding）时允许
  沿着这些软边继续走，这样规则链不会因为 KG 缺边而断掉；最终仍然是
  规则推理分数，不需要 alpha/门控/融合网络。

  ———

  ## 具体如何实现（对齐你当前代码结构）

  你现在的硬 grounding 在 src/data.py:410：

  - x 是 one-hot/计数的 dense 向量（[|E|, batch, 1]）
  - 每一步关系 r_body 用 propagate() 做邻接传播（边权全 1）
  - 输出是 [batch, |E|] 的“可达计数/支持度”

  Soft-Grounding 就是在传播时把边权从全 1 改成 “观测边=1 + 预测边
  =η·p_kge”。

  ### Step 1：新增“带权传播”函数（Weighted Propagate）

  在 KnowledgeGraph 里新增一个函数（不改原 propagate 也行）：

  - 输入：当前分布/计数 x，以及一批边 (src, dst, weight)
  - 传播：message = x[src] * weight，然后对 dst 做 scatter-sum 得
    到下一步 x_next

  观测边：

  - src=node_in、dst=node_out 直接来自
    self.relation2adjacency[relation]
  - weight=1

  预测边（来自 KGE）：

  - 你不可能对全实体建全连接边，所以只取 topB 的尾实体
  - 边权：weight = η * sigmoid((s_kge - b_r)/T_r)（η∈(0,1]，
    T_r>0）

  ### Step 2：为每步关系生成“预测边”（TopB）

  给定一批源节点 src_nodes 和关系 r，拿到 topB tails：

  - 小图（kinship/umls）可以直接算全实体分数：你已有
    model.compute_g_KGE(h,r)（全 tail）
  - 大图（wn18rr/fb15k237）建议做 beam 限制：每步只对每个 query 的
    前沿节点取 topS（比如 4~16 个）作为 src_nodes，对这些 src 才算
    全实体分数并取 topB

  得到：

  - dst_topk：每个 src 对应 B 个 tail
  - score_topk：对应的 RotatE 分数
  - p_topk = sigmoid((score_topk - b_r)/T_r)
  - 预测边列表 (src, dst, η*p_topk)

  ### Step 3：实现 soft_grounding(h, r_head, rule_body,
  edges_to_remove, model, B, S, η, T)

  逻辑基本等价于你现有 grounding()，只是每一步传播时边集变成：

  - 观测边（可选剔除 edges_to_remove，保持你现在防泄漏逻辑）
      - 预测边（TopB），并且当 r_body == r_head 且训练时提供了“当
        前真值 tail”，应当把该 tail 从预测 topB 里剔除，避免用
        teacher 把答案塞回去

  输出仍然是 [batch, |E|] 的 float 支持度（不一定是整数计数了）。

  ### Step 4：在 RulE.forward() 里替换 graph.grounding

  你现在每条规则：

  - count = self.graph.grounding(all_h, r_head, r_body,
    edges_to_remove).float()

  改成：

  - count = self.graph.soft_grounding(all_h, r_head, r_body,
    edges_to_remove, model=self, topb=B, beam=S, eta=η, temp=T)

  后面的 rule_to_entity、score_model 都不用变（先最小改动跑通）。

  ### Step 5：训练/推理怎么用

  - Grounding 训练阶段：count 变成更“软”的支持度，mask（候选）会扩
    大，学习目标不变。
  - 推理阶段：同样用 soft_grounding，候选更全，MRR 往往更稳（尤其
    长规则、多缺边时）。

  实体：A=Alice, B=Bob, C=Carol
  关系：parent(x,y)
  目标关系：grandparent(x,y)
  规则：grandparent(x,y) :- parent(x,z) ∧ parent(z,y)（两跳）

  观测 KG 里只有：

  - parent(A,B)=True
  - parent(B,C)=False（缺边！）

  ### 硬 grounding

  对 query grandparent(A, ?)：

  - 第一步沿 parent：从 A 到 B，前沿是 {B}
  - 第二步沿 parent：B 没有观测到任何 parent(B,·)，前沿变空
  - 输出对 C 的支持度 = 0
    所以模型根本“看不到” C 是候选。

  ### Soft-Grounding（加入 KGE 软边）

  假设 RotatE 给出：

  - s_kge(B, parent, C) 很高，经 sigmoid 后 p_kge(B,parent,C)=0.8
    取 η=0.5，则预测边权 w=0.4

  传播：

  - 第一步观测边：A -> B (weight=1)，所以 x(B)=1
  - 第二步：
      - 观测边仍为空，但预测边提供：B -> C (weight=0.4)
      - 所以 x(C) += x(B) * 0.4 = 0.4

  结果：count(C)=0.4（非零），C 进入候选；后面规则打分/排序就有机
  会把它排上去。

  ## 这套方案的关键超参（建议起步）

  - topB（每个 src 取多少预测尾实体）：小图 50~200；大图 50~500
  - beam S（每步每个 query 保留多少前沿 src）：4~16（大图必须）
  - η（预测边强度）：0.1~0.5 起步（太大容易引噪）
  - T（温度）：1.0 起步；也可以按关系做静态 T_r（valid 上标定）
