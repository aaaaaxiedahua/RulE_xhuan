基于“丢失尾实体”分析的 Grounding 创新方案
1. 为什么会找不到真实尾实体？ (Failure Analysis)
在 RulE 模型的推理过程中，无法召回（Recall）真实尾实体通常有以下三种核心原因：

原因 A：图谱稀疏性导致路径断裂 (The Broken Path Problem)
现象：规则是正确的（例如 
(A, r1, B) ^ (B, r2, C) -> (A, r3, C)
），但在测试图中，中间边 
(A, r1, B)
 或 
(B, r2, C)
 缺失了。
结果：由于 RulE 的 grounding 机制是基于 硬匹配 (Hard Matching) 的（即必须存在明确的边），路径中断导致规则无法激活，真实的 C 永远不会被计入候选集。
占比：在稀疏图谱（如 NELL, KINSHIP 部分数据）中，这是由于信息不全导致的最常见错误。
原因 B：路径存在但被淹没 (The Noise/Hub Problem)
现象：存在大量路径指向错误的尾实体，而指向真实尾实体的路径虽然存在，但在聚合时得分不突出。
例子：中间节点 B 是一个超级节点（Hub），连接了成千上万个无关的 C'。路径 A -> B -> C' 仅仅因为 B 的度数大而大量存在。
结果：Grounding 机制机械地计算路径数量，噪声路径的累积得分（Count）压过了真实路径，导致排序（Ranking）错误。
原因 C：规则覆盖率局限 (The Zero-Shot/Unseen Problem)
现象：头实体和尾实体之间根本不存在符合 预定义规则长度或类型 的路径。
例子：关系需要 4 跳才能到达，但规则最大长度限制为 3 跳；或者需要一种从未在规则集中出现的复杂逻辑组合。
结果：Grounding 搜索不到任何路径，模型回退到仅依赖 Bias 或随机猜测。
2. 针对性 Grounding 创新提案
针对上述分析，特别是 原因 A（断裂） 和 原因 B（噪声），我提出以下针对 Grounding 机制的创新：

创新方案一：弹性落地 (Soft/Elastic Grounding) —— 解决路径断裂
核心思想：将 Grounding 从“硬性的边遍历”改为“概率性的向量遍历”。允许路径中出现 “缺失的一环” (Missing Link)，只要向量空间中的相似度足够高。

原理：
在 Trie 树搜索时，当在节点 $u$ 寻找关系 $r$ 的邻居时，除了查找真实存在的边 $(u, r, v)$，还允许进行一次“虚拟跳跃”。
虚拟跳跃条件：如果没有边，但嵌入向量满足 $E(u) + E(r) \approx E(v)$ (此时利用 KGE 的预测能力)，则临时认为该边存在，继续 Grounding。
实现机制：
Trust Region：只允许在置信度极高的情况下进行虚拟跳跃，防止搜索空间爆炸。
惩罚系数：通过虚拟边到达的路径，其权重（Weight）要乘以一个衰减系数 $\lambda < 1$，表示其置信度低于真实路径。
优势：直接修复了因数据稀疏导致的“路径断裂”问题，大大提高了召回率。
创新方案二：信息熵加权落地 (Entropy-Aware Grounding) —— 解决噪声干扰
核心思想：在 Grounding 过程中，不再简单地计数（Count），而是计算“信息量”。惩罚经过“超级节点”（Hub Nodes）的路径。

原理：
如果中间节点 $B$ 的度数（Degree）非常大，那么路径 $A \to B \to C$ 的证据效力就很低（因为 $B$ 连接了所有人）。
加权公式：在 
_ground_rule_trie
 累加 node_count 时，引入 逆路径频率 (IPF) 权重。
$Weight(Path) = \prod_{node \in Path} \frac{1}{\log(Degree(node) + \epsilon)}$
实现机制：
在预处理阶段计算所有节点的度数权重。
在 Grounding 传播时，顺带传播这个权重乘积。
优势：有效抑制了常见结构带来的噪声，让模型聚焦于那些“独特且具体”的推理路径（Unique Explanations），提升 Precision。
创新方案三：自适应多跳补全 (Adaptive Hops Bridging) —— 综合方案
核心思想：结合上述两者。在 Grounding 遇到死胡同时，如果当前已经匹配了规则的大部分（例如 3 跳规则匹配了 2 跳），启动一个局部的 KGE 预测来“补全”最后一步。

流程：
正常 Grounding 匹配前 $k-1$ 步。
如果最后一步 $r_k$ 缺失，不直接丢弃。
利用此时的路径嵌入 (Path Embedding) 在向量空间中搜索最近邻作为候选尾实体。
这实际上是将 符号推理（前几步） 与 向量推理（最后一步） 串联起来。
3. 推荐实施路线
我建议优先实施 创新方案一 (Soft Grounding)，因为它最直接地回应了“找不到实体”的问题，且通过利用模型已有的 KGE 组件（entity_embedding, relation_embedding）相对容易在代码中实现。

具体代码改动点：

修改 src/graph.py 中的 propagate 函数，增加 soft_mode 参数。
修改 
src/model.py
 中的 
_ground_rule_trie
，在遍历 Trie 子节点时，引入基于向量相似度的邻居搜索（Top-K 近邻）。




====================
  ## 参数

  - K_soft：soft 时取的候选数（固定，比如 16）
  - λ：soft 衰减系数（固定，比如 0.5）
  - τ：softmax 温度（固定，比如 2.0）
  - （可选）th_score / th_gap：soft 触发阈值（先不加也行）

  ## 状态（不使用 beam）

  对每个样本维护一个前沿分布 S（字典/哈希表）：

  - S[u] = weight：当前能到达实体 u 的累计权重（合并累加）
  - 初始：S = {h: 1.0}

  ## 逐跳执行（规则体长度 L，hop i=1..L）

  ### 1) Hard 扩展（先做）

  构造 S_hard = {}
  对每个 u in S：

  - 取真实邻居集合 N_hard(u, r_i)（图中存在边）
  - 对每个 v ∈ N_hard(u,r_i)：
    S_hard[v] += S[u]  （hard 权重先按 1 计）

  如果 S_hard 非空：

  - 令 S = S_hard
  - 进入下一 hop
  - 本 hop 不允许 soft（保守策略）

  ### 2) Soft 扩展（仅当 hard 全断）

  如果 S_hard 为空：
  构造 S_soft = {}
  对每个 u in S：

  - 用 KGE 预测 topK_KGE(u, r_i, K_soft) = [v1..vK]
  - 计算置信度 p(vj) = softmax(score(u,r_i,vj)/τ)（只在这 K 个上归
    一化即可）
  - 对每个 vj：
    S_soft[vj] += S[u] * λ * p(vj)

## 参数（全部可固定，不用 K_soft2 / beam）

  - K_soft：soft 近邻数量（固定一个值，比如 16）
  - λ：soft 路径衰减（每发生一次 soft，就把该分支权重乘 λ；不需要
    记录次数，权重里自然累计）
  - τ：把 KGE 分数转成置信度用的温度（softmax(score/τ)）
  - （强烈建议）H_cap：hard 邻居上限（防 hub 扩张，比如 64）
  - （可选）th_score/th_gap：soft 触发门槛（防幻觉；不想用也能先不
    加）

  ## 状态表示（无 beam）

  对每个样本维护一个“前沿分布” S：{entity -> weight}

  - 初始：S = {h: 1.0}

  > 注意：这里不是 beam，不设固定保留数量；但会对同一实体做合并
  > （累加权重），这是必须的，否则重复路径会无意义膨胀。

  ## 按规则体逐跳执行（长度 L，hop i=1..L）

  对每一跳关系 r_i：

  - 对 S 里的每个实体 u：
      - 取真实邻居 N_hard(u, r_i)（图中存在边）
      - 若 |N_hard| 太大，截断到 H_cap
      - 把所有 v ∈ N_hard 加入 S_hard[v] += S[u] *
        hard_weight(u,r_i,v)
        （hard_weight 可以先取 1；后续再加 hub 惩罚也行）
  - 如果 S_hard 非空：
      - 令 S = S_hard，进入下一跳
      - 这一跳不允许 soft（这就是你说的保守策略：hard 有就走
        hard，soft 不参与）

  ### 2) 如果 hard 全断，再触发 soft

  如果 S_hard 为空（说明当前前沿所有分支在这一步都没有真实边）：

  - 对 S 里的每个实体 u：
      - 用 KGE 预测 topK_KGE(u, r_i, K_soft) -> {v1..vK}
          - 小图可直接算全实体打分取 topK；大图建议 ANN（Faiss/
            ScaNN）
      - 得到置信度 p(v|u,r_i) = softmax(score/τ)（只在 topK 内归一
        化即可）
      - 更新 S_soft[v] += S[u] * λ * p(v|u,r_i)（可选再乘
        hub_weight）
  - 令 S = S_soft，进入下一跳
  - 如果 S_soft 仍为空（topK 没产出/被阈值全过滤）：这条规则路径失
  ## 输出 count/strength（你问的“断掉的算不算”）

  - 走完 L 跳后，S 里的实体就是“完整匹配该规则体（含 soft 补全）的
    尾实体候选”，其 weight 就是贡献强度。
  - 如果某个 soft 中间候选在后续跳走不通而被丢掉：它不计入最终
    count（因为没完成规则体），只有完成到尾实体的才算。

  ## 规模为什么还可控（即使不设 beam）

  - soft 时每个 u 只扩 K_soft 个，所以增长最多是 |S| * K_soft（不
    像硬边可能遇到 hub 一次爆几万，所以必须要 H_cap）。
  - 同一实体会合并累加，避免指数级重复路径“重复计数”导致状态无意义
    膨胀。

 ## 1) GNN 推理替代/增强 grounding（NBFNet / Neural Bellman-Ford
  + A*Net 类搜索改进）

  ### 核心思想

  把“从 (h,r) 推到 t”看成 在图上做有条件的多跳搜索/动态规划，用一
  个 GNN 来近似 Bellman-Ford（最短路/动态规划）式的递推：

  - 每一跳用 relation-aware 的消息传递更新节点状态（表示“从 h 出
    发、在关系条件下到达这里的可行性/路径特征”）。
  - 多跳后，用目标关系 r 的 query 表示来打分每个候选 t。
  - 关键是：模型学的是“推理过程”，不是事后用规则计数/特征去拟合。

  NBFNet 的典型优势：

  - 对多跳推理、组合关系、路径模式比纯 KGE 更强。
  - 可以做 inductive（新实体/新图部分）推理（看具体变体）。
  - 推理是“软的/可微的”，不会像纯 hard grounding 那样遇到 dead-end
    就断。

  A*Net + NBFNet（你提到的“搜索改进”方向）通常在做：

  - 用启发式/学习到的 heuristic 做 更好的候选扩展/剪枝，避免每跳爆
    炸式扩散。
  - 强化“找对路径”而不是“平均扩散”。

  ### 为什么对你现在这个项目可能更有用

  你当前 grounding 其实是：

  1. 用规则在图上 hard propagate 得到候选计数（src/data.py:428,
     src/model.py:590）
  2. 把“规则-候选计数矩阵”丢给 FuncToNodeSum + MLP（src/layers.py,
     src/model.py:646）

  这套在 Kinship（规则短、覆盖高）上已经接近瓶颈；soft 补洞只是修
  补 dead-end，提升空间小。
  NBFNet 类方法则直接把“推理”变成可学习过程，在一些数据集上更容易
  超过“规则计数 + 线性融合”的上限。

  ### 怎么落地到你这套代码（两种落点）

  - A. 直接替换 Grounding predictor：把 RulE.forward() 输出的
    rule_score 换成 NBFNet 输出的 logits，训练沿用
    GroundTrainer.train_step 的监督（target 分布）。
  - B. 作为候选生成器/重排器（更稳更省）：保留你现在 rule
    grounding 的候选，但额外跑一个 NBFNet/GNN 对候选重打分，或者用
    它给出 topK 候选再交给规则模块精排。

  工程上建议先做 B：先把“候选集质量/覆盖”问题解决，成本低、提升更
  稳。

  ## 2) 规则学习/规则增强（SLogic：subgraph-informed rule
  learning；以及“规则增强/扩增”）

  ### 核心思想：规则不是全局静态的

  你现在用的是外部挖的 mined_rules.txt（RNNLogic 产物），训练时所
  有 query 共享同一批规则集合，规则也不会“因 query 而变”。
  SLogic 这类方向通常做两件事：

  1. 子图/局部结构引导规则：对每个 query (h,r,?)，从 h 周围检索一
     个小子图（k-hop、路径集合、重要节点/边），在这个子图上学习/选
     择更相关的规则或路径模式。
  2. 更强的规则筛选/组合：不是“所有规则一起算”，而是针对 query 选
     择少量高相关规则（或者生成/改写规则），减少噪声、提升可解释性
     与泛化。

  “规则增强/扩增”类工作（2024 那条线）常见做法：

  - 从已有规则出发做 对称/逆关系/链式组合 的增广
  - 做 规则体的扰动/重写 来提升覆盖
  - 或用简单的逻辑变换产生更多候选规则，再用模型/统计过滤

  ### 为什么可能有效

  你日志里其实已经看到：soft grounding 经常补出“仍然走不动”的尾实
  体（droppedSoftDead 大），说明你真正缺的是：

  - 某些 query 的局部结构信息没被规则覆盖
  - 或者全局规则对特定 query 来说噪声太多，影响学习

  子图引导/规则选择会显著降低这种“无关规则堆叠”的问题，通常比单纯
  调 soft 参数更有用。

  ### 怎么落地到你现在代码

  最小可做的版本（不用重写 rule miner）：

  - Query-specific 规则选择（Top-M rules per relation/head
    neighborhood）
      - 对每个关系 r，你现在 relation2rules[r] 里可能有很多规则。
      - 可加入一个 gating/attention：根据 (h,r) 的局部子图特征（比
        如 h 的度、h 的邻居关系分布、或一小段 path embedding），选
        Top-M 规则参与 candidate_strength 计算或后续打分。
      - 这能减少 FuncToNodeSum 里被大量噪声规则平均的情况（mean 聚
        合本身就会抹平信号）。

  更进一步（中等改动）：

  - 子图检索 + 路径特征
      - 在 TrainDataset.__getitem__ 里你已经能拿到 (h,r,t)，可以额
        外返回 h 的 k-hop 子图摘要（不用全图，只要采样）。
      - 用一个小 GNN/Transformer 编码子图，再输出 rule gate 或直接
        输出 logits（这就开始走向“GNN reasoning”了）。

  ## 3) 融合与置信度（Rule-Guided Joint Embedding / rule
  confidence learning）

  ### 核心思想

  不要把规则和 KGE 当成两个模块“最后加一下”，而要：

  - 联合训练（joint)：让 embedding 学到“更符合规则”的几何结构，同
    时让规则模块学到“更依赖 embedding 的部分”
  - 置信度/权重可学习：对每条规则、每个关系、甚至每个 query，学习
    它应当有多大权重；低质量规则自动降权，避免拉低效果

  你旧实验日志里出现过 RuleConf，这就是“rule confidence
  learning”雏形：学习每条规则一个置信度参数，用来重标定 rule
  contribution。

  ### 为什么你现在“感觉没提升”

  你当前 src/ 主流程里：

  - grounding 训练只优化 grounding_rule_score（src/
    trainer.py:500），不把 KGE 融合放进训练目标；
  - 规则贡献是“规则计数 + multiplicity”再喂给 FuncToNodeSum，并没
    有显式“规则置信度学习”（你当前 src/kinship/run.log 里也已经没
    有 RuleConf 打印了）。

  所以你会看到：即使你调 soft，最终还是靠 KGE 主导 test_kge，规则
  侧的任何增益被稀释。

  ### 怎么落地（最有性价比的两个）

  - A. 训练期融合（而不是只在 test_kge 加 alpha）
      - 把 kge_score 加进 GroundTrainer.train_step 的 logits 再算
        loss（现在只在 evaluate_t 里加，src/trainer.py:651）。
      - 这会让训练信号对齐你最终使用方式，比调 soft 更可能带来真实
        test_kge 提升。
  - B. 学习可变融合权重
      - alpha 做成 alpha_r（每个关系一个可学习标量），或
        alpha(h,r) 的小网络。
      - 这样“规则强的关系少依赖 KGE；规则弱的关系多依赖 KGE”，通常
        比固定 alpha 更稳。
  - C. Rule confidence（恢复/升级 RuleConf）
      - 每条规则一个 w_rule，参与 candidate_strength 或参与
        FuncToNodeSum 的加权聚合；
      - 加正则防止全变 0/全变大；
      - 并在日志里输出分布（你旧日志已经验证这类统计很有用）。

  ## 方案名称：Pair‑Subgraph Reasoner (GraIL-style)

  ### 输入/输出

  - 输入：查询 (h, r, ?)（训练时有真值 t+）
  - 输出：对每个候选 tail t 的打分 score(h,r,t)，用于排名（MRR/
    Hits）

  ———

  ## 1) 候选集合怎么来（召回，不靠规则）

  测试时要对所有实体排名太贵，所以派2通常做两阶段（召回→精排）：

  - 召回（Retriever）：给每个 (h,r) 取一个候选集合 C（比如
    256/512/1024 个）
      - 推荐默认：C = topK_KGE(h,r)（用你现成的 compute_g_KGE）
      - 备选：C = k-hop 邻域扩展(h)（纯结构，不用KGE，但召回可能
        差）
  - 训练时：为了让 loss 可学，强制 t+ ∈ C（只用于训练，验证/测试不
    加）

  > 这一步是“保证 recall”，否则你后面 GNN 再强也白搭。

  ———

  ## 2) 中间证据节点从哪来（enclosing subgraph）

  对每个候选 tail t ∈ C，构造一个以 (h,t) 为中心的 enclosing
  subgraph：

  - 取 N_k(h)：从 h 出发 k-hop 采样邻域
  - 取 N_k(t)：从 t 出发 k-hop 采样邻域
  - 子图节点：S = N_k(h) ∪ N_k(t)（可选只取交集附近更干净）
  - 子图边：从原图中抽取端点都在 S 的边（保留 relation type）

  采样控制（必须有，不然爆炸）

  - 每个节点每 hop 最多采样 M 条边（或按 relation 分配预算）
  - 子图最大节点数 max_nodes（超了就截断/优先保留离 h/t 近的）

  防泄漏

  - 训练时把正例边 (h,r,t+) 从子图里删掉（类似你现在的
    edges_to_remove 逻辑）

  ## 3) GNN 用什么特征（派2的关键：结构标签）

  派2的典型特征不是 KGE 分数，而是结构位置编码，最经典的是 DRNL/双
  距离标签：

  - 计算每个子图节点 v 到 h 的最短路距离 d_h(v)
  - 计算到 t 的最短路距离 d_t(v)
  - 节点标签：label(v) = f(d_h(v), d_t(v))（常见做法是把 (d_h,d_t)
    映射成一个整数 id，再做 embedding）

  可加的附加特征（可选，不影响“派2本体”）：

  - is_head, is_tail 标记
  - relation query embedding emb(r) 作为全局条件输入到打分头
  - 你现成的 entity embedding（RotatE）可以作为额外特征，但建议先
    不加，先验证纯结构是否有效

  ———

  ## 4) GNN 结构（关系感知）

  子图边带有 relation type，所以用关系感知层，例如简化 R-GCN（你
  repo 只有 torch-scatter，不用 PyG 也能写）：

  每层：

  - message：m = W_rel x_u（或 MLP([x_u, emb(rel)])）
  - 聚合：按边的目标点 v 做 scatter_add
  - 更新：x_v = ReLU(LN(x_v + agg)) 或 GRU

  ———

  ## 5) 如何给候选打分（graph-level / pair-level scoring）

  跑完 L 层后取子图中 h 节点和 t 节点的 embedding：

  - z = concat(x_h, x_t, emb(r))
  - score(h,r,t) = MLP(z) 输出一个标量

  这就是你要的“不是重排旧 grounding 路径”：它学习的是子图结构模

  ———

  ## 6) 训练方式（不需要全实体 softmax）

    topK 里排前但不为真值的）
  - 对每个候选构造子图并打分
  - 用 pairwise ranking loss 或 listwise softmax：
      - L = -log σ(score(h,r,t+) - score(h,r,t-))（多负例求和/平
